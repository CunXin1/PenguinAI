# Signal Generation Pipeline

## English

### Overview

The signal pipeline transforms market data into a structured investment signal through a sequence of steps, each implemented as a separate module for testability and replaceability.

> **Implementation status.** The orchestration (`signal_engine.compute`) is wired
> end-to-end, but several inputs are not populated yet and **degrade gracefully**:
> the ML models aren't trained (`predict_*` → `None`), `social_posts` is empty
> (sentiment/RAG → neutral/empty), and `celebrity_holdings` / `fomc_statements`
> are empty (smart-money and macro filter no-op). Gemma 4 needs a running LLM
> backend (Ollama / vLLM / API) — see [llm-serving.md](./llm-serving.md); when it's
> down the pipeline falls back to an ML-only signal. See [TODO.md](../TODO.md) for the gaps.

### Step-by-Step Breakdown

#### Step 1 — Load the latest feature row

**File**: `ml/inference/signal_engine.py:_load_features()`

Reads the most recent **model-ready feature row** for the ticker from the
`indicators_30min` view (`SELECT {FEATURE_COLS} … ORDER BY time DESC LIMIT 1`).
The view already exposes the exact `FEATURE_COLS` the trainer saw — precomputed
indicators + scale-free derivations over `bars_30m` — so there is **no
on-the-fly recomputation** at serve time. This is the train/serve-parity
guarantee.

If no row exists for the ticker, a NEUTRAL fallback signal is returned
immediately with reason `"insufficient_data"`.

#### Step 2 — Feature vector

**File**: `ml/features/technical.py:features_to_dict()`

The row from Step 1 is already model-ready; `features_to_dict()` just maps it to
the dict the models expect — no recomputation. The `pandas-ta` path
(`compute_features()`) is the **offline build** path that produced these columns
during the parquet build (`backend/scripts/market_data/compute_indicators.py`).
Both derive the same `FEATURE_COLS` — the single source of truth in
`ml/models/xgboost_trainer.py`.

The feature set exposed by `indicators_30min` / `FEATURE_COLS`:

| Feature | Formula | Purpose |
|---------|---------|---------|
| `rsi_14` | RSI(14) | Momentum overbought/oversold |
| `macd` | MACD(12,26,9) line | Trend direction |
| `macd_signal` | Signal line | Trend confirmation |
| `macd_hist` | Histogram | Momentum acceleration |
| `bb_pct_b` | (close−lower)/(upper−lower) | Position in Bollinger Band |
| `bb_width` | (upper−lower)/middle | Volatility level |
| `atr_14_pct` | ATR(14)/close | Normalized volatility |
| `price_vs_sma200` | close/SMA200 − 1 | Bull/bear regime |
| `price_vs_ema50` | close/EMA50 − 1 | Medium-term trend regime |
| `vwap_pct` | (close−VWAP)/VWAP | Institutional price reference |
| `ret_1bar` | close/close[−1] − 1 | Most recent 30-min return |

Missing values stay as NULL/NaN — XGBoost/RF handle them natively.

#### Step 3 — ML Model Inference

**File**: `ml/models/model_registry.py`

Both models predict `P(close[t+16] > close[t])` — the probability that price will be higher 8 hours from now (16 × 30-min bars).

```python
xgb_prob_up  = model_registry.predict_xgb(ticker, feature_dict)   # 0.0–1.0
rf_prob_up   = model_registry.predict_rf(ticker, feature_dict)    # 0.0–1.0
ensemble     = xgb_prob_up * 0.6 + rf_prob_up * 0.4              # weighted ensemble
```

If either model is not loaded (models not yet trained), returns `None`. The Gemma agent handles `None` gracefully.

#### Step 4 — Sentiment Aggregation

**File**: `ml/features/sentiment.py:get_ticker_sentiment()`

Queries `social_posts` for the past 72 hours, computing:
- `finbert_score`: mean of all `finbert_score` values for this ticker
- `post_count`: number of posts found

FinBERT scoring of new posts happens separately in the Celery scraper task (`realtime_ingest.py`), not here. This step only aggregates already-scored posts from the DB.

#### Step 5 — RAG Retrieval

**File**: `ml/rag/retriever.py:retrieve()`

Retrieves the top-5 semantically relevant post snippets for the ticker using pgvector cosine similarity:

```sql
SELECT content FROM social_posts
WHERE ticker = :ticker AND time >= now() - INTERVAL '72 hours'
ORDER BY embedding <=> :query_embedding
LIMIT 5
```

The query embedding is generated by encoding `"{ticker} stock investment analysis"` (or a custom query if provided) with MiniLM-L6.

**Metadata filter is hardcoded** — results are always restricted to the specific ticker and time window. Cross-ticker contamination is architecturally impossible.

#### Step 6 — Context Assembly (Gemma Agent 1)

**File**: `ml/inference/gemma_agent.py:assemble_context()`

Pure Python function — no LLM call. Builds a structured JSON context from all previous step outputs:

```json
{
  "ticker": "NVDA",
  "ml_signals": {
    "xgb_prob_up": 0.75,
    "rf_prob_up": 0.71,
    "ensemble_prob_up": 0.74
  },
  "sentiment": {
    "finbert_mean_score": 0.68,
    "post_count_72h": 15,
    "sample_posts": ["NVDA breaking out...", "..."]
  },
  "macro_filter": {
    "fomc_hawk_dove_score": -0.2,
    "interpretation": "neutral macro environment"
  },
  "smart_money": [
    {"celebrity": "cathie_wood", "action": "BUY", "reported_at": "2026-05-30"}
  ],
  "fundamentals": {
    "earnings_surprise_pct": 8.5,
    "pe_ratio": 42.3
  }
}
```

#### Step 7 — Gemma 4 Reasoning (Agent 2)

**File**: `ml/inference/gemma_agent.py:reason()`

Sends the assembled context to Gemma 4 through a pluggable backend (Ollama on
macOS / vLLM on Windows·Linux GPU / external API) with a strict system prompt and
JSON Schema locked output format. The backend is selected by `LLM_BACKEND` and
resolved in `ml/inference/llm/factory.py`. See [llm-serving.md](./llm-serving.md)
for deployment, config, and finetune seams.

**System prompt excerpt:**
> "You are a strict quantitative analyst AI. Base your reasoning ENTIRELY on the data provided. Do not use outside knowledge."

**Output validation** (`_validate_output()`):
- `direction` must be `LONG | SHORT | NEUTRAL` — defaults to NEUTRAL if invalid
- `confidence` clamped to [0.0, 1.0]
- `holding_period` must be in enum — defaults to SHORT_TERM
- `ai_attribution` — prompt asks for ≤150 chars; hard-capped (truncated) at 300 chars
- `ai_analysis` — prompt asks for ≤300 chars; hard-capped (truncated) at 600 chars

**Retry policy**: 3 attempts with 2^attempt second delays (2s, 4s backoff).

#### Step 8 — FOMC Macro Filter

**File**: `ml/inference/signal_engine.py:_apply_macro_filter()`

Applies a global risk damper when the Federal Reserve is hawkish:

```python
if hawk_dove > 0.5 and direction == "LONG":
    confidence *= 0.85
    if confidence < MIN_CONFIDENCE_THRESHOLD:  # default 0.55
        direction = "NEUTRAL"
```

This ensures that strongly bullish signals generated during aggressive rate-hike environments are dampened, reflecting increased macro risk.

### Signal Output Schema

```python
{
    "ticker": str,                      # "NVDA"
    "direction": "LONG"|"SHORT"|"NEUTRAL",
    "confidence": float,                # 0.0–1.0
    "holding_period": "INTRADAY"|"SHORT_TERM"|"SWING"|"POSITION",
    "xgb_prob_up": float | None,
    "rf_prob_up": float | None,
    "ensemble_prob": float | None,
    "finbert_score": float | None,      # -1.0 to 1.0
    "post_count": int,
    "hawk_dove_ref": float | None,
    "ai_attribution": str,              # ≤150 chars, key drivers
    "ai_analysis": str,                 # ≤300 chars, professional summary
    "tier_required": "FREE"|"PRO"|"PREMIUM",
    "computed_at": datetime,
    "expires_at": datetime,             # +1h (top-100) or +4h (cold)
}
```

### Holding Period Mapping

| Value | Meaning | Primary Signal Source |
|-------|---------|-----------------------|
| `INTRADAY` | Same-day exit | 1-min momentum + sentiment spike |
| `SHORT_TERM` | 1–3 trading days | 30-min trend + ML ensemble 50-70% |
| `SWING` | 1–2 weeks | Strong ML signal + fundamentals |
| `POSITION` | Weeks to months | Macro alignment + celebrity + strong ML |

## 中文

### 信号生成八步流水线

| 步骤 | 模块 | 内容 |
|------|------|------|
| 1 | `signal_engine._load_features()` | 从 `indicators_30min` 视图读取最新一行模型就绪特征（无需实时重算） |
| 2 | `features/technical.py:features_to_dict()` | 将特征行映射为模型输入字典（`pandas-ta` 仅用于离线构建） |
| 3 | `models/model_registry.py` | XGBoost + 随机森林推理，预测 8 小时后涨跌概率 |
| 4 | `features/sentiment.py` | 聚合 72 小时内该股票的 FinBERT 情绪均值 |
| 5 | `rag/retriever.py` | pgvector 余弦相似度检索，返回 Top-5 相关帖子 |
| 6 | `gemma_agent.assemble_context()` | 纯 Python 组装结构化上下文 JSON（无 LLM 调用） |
| 7 | `gemma_agent.reason()` | Gemma 4 推理，JSON 模式锁定输出，3次重试 |
| 8 | `signal_engine._apply_macro_filter()` | FOMC 鹰派时压制做多置信度 |

### 关键设计决策

**为什么 Agent 1 不调用 LLM？**
数据组装是确定性的（无需智能），放在纯 Python 中执行可以并行运行、完全可测试，且不消耗 LLM token。只有最终的综合推理和文字归因才需要 Gemma 4。

**为什么 RAG 元数据过滤是硬编码的？**
避免跨股票信息污染。如果不强制 `ticker` 和 `time` 过滤，向量相似度搜索可能返回其他股票的相关帖子，导致推理出错。
